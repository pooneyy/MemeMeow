## Purpose

为使用 OpenCode 的 Agent 任务提供按模型区分的工作轮次预算、提前收尾提醒和最终停止规则，并让执行控制、任务状态和用户界面使用同一份可恢复的轮次事实。

## ADDED Requirements

### Requirement: 每个模型必须有可冻结的轮次策略

系统 MUST 为每个允许执行 Agent 任务的模型提供受约束的轮次策略。策略 MUST 至少包含正常轮次上限、提醒轮次和宽限轮次数；硬停止轮次 MUST 等于正常轮次上限加宽限轮次数。提醒轮次 MUST 为正整数且不得大于正常轮次上限。任务创建或恢复时 MUST 保存实际生效的模型、变体和完整策略快照，之后模型目录变化不得改写该任务的策略。

#### Scenario: 创建任务冻结模型策略
- **WHEN** 用户使用正常轮次上限为 10、提醒轮次为 9、宽限轮次为 5 的免费模型创建 Agent 任务
- **THEN** 任务保存该策略快照，硬停止轮次为 15，后续配置刷新不改变该任务的 10、9、5 数值

#### Scenario: 策略配置无效
- **WHEN** 模型缺少轮次策略，或提醒轮次、正常轮次上限、宽限轮次数不满足约束
- **THEN** 系统拒绝创建任务并返回稳定的配置错误，不以无限轮次继续执行

### Requirement: 系统必须从运行输出形成唯一轮次事实

系统 MUST 从当前 Agent 任务主 OpenCode session 的结构化运行输出识别轮次开始和结束，并按事件部件的稳定标识去重。一个轮次表示一次模型步骤；一个轮次可以包含多个工具调用。系统 MUST 同时维护已完成轮次数、当前是否有未完成轮次和最近活动时间，并让轮次限制和任务状态使用同一份值。无法确认事件所属任务、事件标识重复冲突或结构化输出无法解析时，系统 MUST 明确记录轮次跟踪错误，不得静默恢复为无限执行。

#### Scenario: 轮次事件同时供控制和页面使用
- **WHEN** 当前任务收到第 9 个唯一的轮次开始事件，且前 8 个轮次已经结束
- **THEN** 轮次状态为已完成 8 轮、当前第 9 轮进行中，任务控制进入提醒阶段，任务状态接口返回相同的轮次值

#### Scenario: 重复事件不重复计数
- **WHEN** 同一个轮次开始或结束事件因为流重放被收到多次
- **THEN** 系统按事件部件标识只计数一次，页面和硬限制都保持一致

#### Scenario: 输出无法解析
- **WHEN** OpenCode 输出出现无法解析的结构化行，或无法确认其属于当前任务主 session
- **THEN** 系统记录稳定的轮次跟踪错误并停止继续扩大轮次预算，不把未知事件当作已完成轮次

### Requirement: 接近上限时必须尽力向模型发送一次收尾提醒

系统 MUST 使用 OpenCode 现有插件接口，尽量在任务进入配置的提醒轮次时向当前模型请求追加收尾提醒，要求模型优先完成必要工作、验证已有结果并生成报告。由于插件接口不提供可靠的主任务轮次编号，系统 MUST NOT 承诺提醒一定精确出现在配置轮次；标题生成、上下文压缩或子任务使当前轮次无法确认时，提醒可以提前、延后或漏发。该提醒 MUST 只影响模型上下文，不得伪造新的用户任务或增加轮次。每个任务 attempt MUST 最多发送一次提醒；提醒不是强制停止，提醒是否成功不得改变 Executor 的硬停止判断。

#### Scenario: 能够确认第 9 轮时发送提醒
- **WHEN** 任务策略的提醒轮次为 9，且插件根据主 session 和当前模型确认当前请求是第 9 个主任务轮次
- **THEN** 当前请求包含收尾提醒，系统记录提醒已发送，并允许该轮及后续宽限轮次继续执行

#### Scenario: 插件无法准确确认提醒轮次
- **WHEN** 标题生成、上下文压缩或子任务使插件无法确认当前请求是不是第 9 个主任务轮次
- **THEN** 系统允许提醒提前、延后或漏发，不把提醒结果当作轮次限制依据，Executor 仍按结构化运行输出执行硬停止

#### Scenario: 提醒不重复发送
- **WHEN** 同一 attempt 因请求重试或重复事件再次进入提醒判断
- **THEN** 系统不重复追加提醒，也不额外创建用户消息

### Requirement: 超过硬停止轮次必须停止 Agent 进程

系统 MUST 允许模型完成“正常轮次上限加宽限轮次数”以内的轮次。当结构化运行输出出现下一个唯一的 `step_start` 时，系统 MUST 立即终止该任务对应的 OpenCode 进程组。该下一轮模型请求可能已经发出并产生费用，系统不保证在请求发出前拦截，但 MUST 在观察到开始事件后立即进入终止流程，不允许该轮继续工作。终止 MUST 使用现有的任务进程回收和 wait 语义，不能只向模型发送文字提示。被轮次限制终止的任务 MUST 进入失败或明确的中断终态，返回稳定错误 `agent_turn_limit_exceeded`（或版本化的等价错误），不得把未完成的结果报告为成功。

#### Scenario: 宽限五轮后强制停止
- **WHEN** 任务正常轮次上限为 10、宽限轮次数为 5，且 Executor 收到第 16 个唯一的 `step_start`
- **THEN** 系统接受第 16 次模型请求可能已经开始这一事实，立即终止该任务的 OpenCode 进程组，使任务进入可诊断终态并返回 `agent_turn_limit_exceeded`，不影响其他任务

#### Scenario: 轮次限制终止后保留诊断
- **WHEN** 系统因轮次限制终止任务
- **THEN** 已写入的结果草稿、session 标识、最后轮次快照和终止原因按现有诊断规则保留，且任务不可被误判为成功

### Requirement: 恢复任务必须继续消耗累计轮次预算

系统 MUST 将任务及其 attempt 已消耗的轮次持久保存。恢复同一 OpenCode session 或重新启动执行进程时 MUST 使用原任务策略和累计消耗值，不能因为进程、Worker 或服务重启而重新获得完整正常轮次和宽限轮次。旧 attempt 的迟到事件 MUST NOT 覆盖新 attempt 的轮次快照或终态。

#### Scenario: 恢复任务沿用剩余额度
- **WHEN** 一个任务在第 8 轮结束后执行器重启，并以同一 session 恢复
- **THEN** 恢复执行从累计 8 轮继续计算，仍按原策略在提醒和硬停止边界收束

#### Scenario: 过期 attempt 不能写回
- **WHEN** 旧执行器租约失效后，新执行器已经接管任务，旧进程又发送轮次事件
- **THEN** 系统拒绝旧事件的轮次、活动时间和终态写回，并保留新执行器的事实

### Requirement: 提醒插件必须可验证且不得成为安全边界

任务启动前 MUST 验证与当前 OpenCode 版本匹配的轮次提醒插件已从受保护位置加载。启动前找不到插件、加载失败、初始化失败或版本不兼容时，系统 MUST 在第一次模型调用前返回明确的任务错误。插件成功启动后，单次提醒判断或提示注入发生运行时异常时，系统 MUST 记录明确的提醒错误并允许任务继续，但不得假装提醒已经发送。插件可以读取任务策略并修改模型请求提示，但 MUST NOT 负责最终轮次裁决、计费、权限隔离或进程回收。

#### Scenario: 插件加载失败
- **WHEN** 任务启动时找不到插件、插件版本不兼容或插件初始化失败
- **THEN** 任务在模型调用前进入明确失败状态，并记录插件错误，不以没有提醒的方式继续运行

#### Scenario: 插件异常不绕过硬限制
- **WHEN** 提醒插件在模型请求期间异常或未能修改提示
- **THEN** 系统记录本次提醒失败并允许任务继续，Executor 仍根据统一轮次事实执行硬停止规则，插件异常不会把任务变成无限轮次
