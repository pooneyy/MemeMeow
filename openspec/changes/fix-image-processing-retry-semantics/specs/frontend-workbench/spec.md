## ADDED Requirements

### Requirement: 前端必须区分完整重试和修复未就绪
图片库 MUST 将对选中图片强制执行全部已启用阶段的操作显示为“完整重试”，并将 scope 级只处理问题部分的操作显示为“修复所有未就绪”。确认界面 MUST 用简短文字说明两种操作的执行范围，不得继续使用“完整重试所有未就绪”这一容易混淆的名称。

#### Scenario: 用户确认选中图片完整重试
- **WHEN** 用户选择图片并打开完整重试确认界面
- **THEN** 界面说明所有已启用阶段都会重新执行，即使已有结果仍然有效

#### Scenario: 用户确认修复所有未就绪
- **WHEN** 用户打开“修复所有未就绪”确认界面
- **THEN** 界面说明服务端只为存在问题的图片和阶段创建修复任务

### Requirement: 批量结果必须逐图解释冲突和失败
批量修复完成提交后，前端 MUST 展示已提交、正在处理、无需修复和提交失败的数量，并允许用户看到每张未提交图片的稳定原因。某张图片正在处理时，界面 MUST 明确说明只有该图片被拒绝，不能把整批操作显示为失败。

#### Scenario: 批量修复部分冲突
- **WHEN** 服务端返回部分图片 `image_processing_active`，其余图片已提交
- **THEN** 前端分别展示已提交数量和正在处理数量
- **AND** 在逐图结果中说明冲突图片正在处理，其他图片已继续修复
