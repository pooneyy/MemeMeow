## 2. 创建时确定执行范围

- [x] 2.1 抽取服务端阶段就绪判断和依赖计算，使普通处理与修复在父 Job 创建前生成固定计划，并避免在数据库事务中读取文件或执行耗时操作。
- [x] 2.2 修改选中图片完整重试和终态 Job retry，使其为全部已启用阶段写入计划并始终创建新的 revision，不按已有产物缩小范围。
- [x] 2.3 实现修复计划规则：视觉问题只修复视觉；Agent 问题修复 Agent、启用的自动重命名和文本向量；自动重命名 warning 只修复自动重命名；文本问题只修复文本；多个问题取合集。
- [x] 2.4 修改 Worker 推进逻辑，使其只执行持久计划并为每个计划内阶段创建新的叶子 Task；把原运行时有效性检查收窄为目标、输入和执行身份安全校验。
- [x] 2.5 在进入依赖阶段和父 Job 收束前复核创建时跳过阶段所绑定的输入；失效时以 `image_processing_plan_stale` 明确停止，不在运行时扩大计划。
- [x] 2.6 增加完整重试、各类最小修复范围、服务重启恢复、目标变化、跳过依据失效、已有叶子 Task恢复和计划内旧产物仍有效的定向测试。
